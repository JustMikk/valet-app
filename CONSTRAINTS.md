# Constraints

Last reviewed: 2026-10-22 by @Mikiyas

The quality bar for this repo. Every check blocks: a failing check is fixed in the code, never by
editing this file in the same change. Tightening is welcome; loosening needs the owner's sign-off
in its own commit, and `pnpm guard` flags it. Sources: build handoff §7 (code quality), §5.1
(Capacitor-ready), §5.3 (layers), §8.3 (evidence).

## Floor (always enforced)

- No new suppression comments: `@ts-ignore`, `@ts-nocheck`, `eslint-disable`, `istanbul/v8/c8 ignore`, `nosemgrep`, `gitleaks:allow` (handoff §7: "do not silence lint rules")
- No unimplemented stubs: `throw new Error("Not implemented")`, empty `catch {}`, `TODO`/`FIXME` left in code
- No skipped or deleted tests, and no assertions removed from tests that stay
- No secrets in source or history (reported redacted, never by value)
- No new path in `.constraintsignore` without an Exceptions row
- This file does not get weakened to make a change pass

Checked by `pnpm guard` (`scripts/floor-guard.mjs`, diff-scoped, exit 0 clean / 1 violation / 2 could not run) and `pnpm secrets`.

## External opinions

gitleaks, osv-scanner, `pnpm audit`, Semgrep, axe-core and Lighthouse judge the code against outside rules or databases. They are the checks an agent cannot satisfy by writing tests that agree with itself.

## Known environment issues

- **Vitest worker start-up on Windows.** Vitest's fork pool has a hard-coded 60 s start timeout (`START_TIMEOUT` in vitest 5.0.5). On this Windows laptop the first worker occasionally exceeds it (likely antivirus scanning the new Node process); tests themselves take ~3 s. Rerun once. Do not add test retries or raise timeouts to hide it; if it recurs on CI (Linux), treat it as a real failure.
